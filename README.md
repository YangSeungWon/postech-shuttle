# POSTECH 셔틀버스 지도

공개 셔틀버스 시간표를 지도 위에서 보여 주는 정적 웹페이지입니다.
`bus.ysw.kr` 에 GitHub Pages로 배포합니다.

* **지도** `index.html` — 노선·정류장, 시간표로 계산한 버스 위치, 내 위치 기준 도착 예정, 길찾기
* **시간표** `timetable.html` — 기존 안내 페이지

> 버스 위치와 도착 시각은 **공개 시간표를 보간한 예상값**이며 차량 GPS가 아닙니다.
> 교통 상황에 따라 1~2분 차이가 날 수 있습니다.

## 구조

런타임에는 지도 타일 말고 외부 호출이 없습니다. 시간표, 도로를 따라가는
노선 도형, 캠퍼스 건물 좌표, 보행 그래프를 전부 빌드 때 파일로 구워 넣습니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 화면과 스타일 |
| `map.js` | 지도·패널·길찾기 UI |
| `planner.js` | 시간표 기반 경로탐색 (RAPTOR 계열) |
| `walk.js` | OSM 보행 그래프 위의 Dijkstra (경사·횡단보도 반영) |
| `i18n.js` | 국문·영문 화면 문구 |
| `map-data.js` | 빌드 산출물 (노선·정류장·건물·보행 그래프·영문 표기) |
| `style-muted*.json` | 바탕 지도 벡터 스타일 (국문/영문 라벨) |
| `sw.js` | 오프라인 캐시 (빌드 산출물, `sw.tmpl.js` 에서 생성) |
| `manifest.webmanifest` | 홈 화면 추가 |
| `source.json` | 시간표 시행일과 마지막 확인 날짜 |

## 다시 빌드하기

```sh
python3 basemap.py                                  # 바탕 지도 스타일
python3 build.py                                    # map-data.json · sw.js 생성
python3 -c "print('const DATA = '+open('map-data.json').read()+';')" > map-data.js
```

`build.py` 는 소스 파일들의 해시로 오프라인 캐시 버전(`sw.js`)을 만듭니다.
**소스를 고친 뒤에는 반드시 다시 돌려야** 사용자에게 옛 코드가 남지 않습니다.

`build.py` 는 다음을 조합합니다.

* `data.json` — 기존 안내 페이지에서 추출한 노선·시간표
* `stops.py` — 정류장 좌표와 구간별 경유지(`VIA`)
* `pois.py` — OSM에서 뽑은 캠퍼스 건물 (목적지 후보)
* `walkgraph.py` — OSM 보행 그래프
* `holidays.py` — 운행일 (평일만 운행, 공휴일은 hyunbinseo/holidays-kr)
* `upstream.py` — 원본 시간표를 다시 받아 비교
* `fetch_osm.py` — OSM 도로·건물 다시 받기 (`refresh.py --osm`)
* `basemap.py` — 바탕 지도 벡터 스타일 (`style-muted*.json`)
* `i18n_src.py` — 기존 안내 페이지의 영문 정류장·노선명
* `names_en.py` — POSTECH 공식 영문 건물명 (캠퍼스 안내도 국·영문 대조)
* `elevation.py` — 그래프 노드의 고도 (SRTM 30m, `elev_cache.json.gz` 에 캐시)
* `driveroute.py` — 정류장 사이 차량 경로 (같은 OSM 추출본에서 직접 계산)

원본 OSM 덤프(`osm.json.gz`, `walk.json.gz`)와 고도 캐시(`elev_cache.json.gz`)가
저장소에 있어 네트워크 없이도 다시 빌드할 수 있습니다.

## 도보 시간 계산

캠퍼스 고저차가 40m 넘게 나서(효자시장 6m ~ 나노융합기술원 57m) 평지 가정으로는
실제와 어긋납니다. 특히 양방향 소요시간이 같게 나오는 것이 문제였습니다.

보행 그래프의 **구간마다** 그 방향의 경사로 속도를 따로 구합니다(Tobler 도보 함수,
평지 4.5km/h 기준으로 정규화). 출발·도착 고도차만 보면 "올라갔다 내려오는" 구간이
사라지므로 구간 단위로 계산해야 합니다. 계단은 ×1.8, 비포장 ×1.2 를 더 곱합니다.

SRTM 30m 고도는 지점별로 몇 m 씩 튀므로 이웃 노드 평균으로 한 번 다듬습니다.
다듬지 않으면 없는 오르내림이 생겨 시간이 부풀려집니다.

보행 그래프에는 횡단보도(129곳)가 포함되어 있어 길찾기가 실제 건널목으로
길을 건넙니다. 지도에서는 가까이 봤을 때(z17 이상) 옅게 깔고, 안내 중인
경로가 실제로 건너는 곳은 얼룩말 무늬로 진하게 보여 줍니다.

## 정류장 좌표

정류장 표지판의 정확한 좌표는 공개 데이터에 없어 처음에는 건물·도로 기준
근사값으로 시작했고, 지도에서 직접 보정해 `stops.py` 에 반영했습니다
(평균 103m, 최대 249m 이동).

좌표 보정 도구는 평소에는 감춰 둡니다. 주소에 **`?edit`** 를 붙이면(예:
`bus.ysw.kr/?edit`) 우하단에 ✎ 버튼이 나옵니다. 켜면 자동으로 z17 까지 확대돼
양방향 정류장이 갈라지고, 마커를 끈 다음 **JSON 복사**를 눌러 `stops.py` 의
`STOPS` 에 붙여 넣고 다시 빌드하면 됩니다. OSRM 캐시는 좌표를
키에 넣으므로 옛 경로가 재사용되지 않습니다.


## 바탕 지도

래스터 타일에 흑백 필터를 씌우면 도로 위계와 라벨까지 함께 뭉개져서, 바탕이
물러나는 게 아니라 그냥 흐려지기만 한다. 벡터 스타일(OpenFreeMap, 키 불필요)을
직접 손봐서 땅과 건물은 물리고 길과 이름만 남긴다. WebGL 이 없는 환경에서는
래스터 OSM 으로 물러난다.

## 언어

국문·영문을 지원한다. 화면 문구는 `i18n.js`, 정류장·노선 영문명은 기존 안내
페이지(`timetable.html`)의 것을 그대로 쓰고, 건물 영문명은 POSTECH 공식 캠퍼스
안내도의 국·영문 페이지를 `data-id` 로 대조해 만든다. 검색은 한글·영문 어느
쪽으로 쳐도 찾힌다. 지도 라벨도 언어에 따라 바뀐다.


## 노선 도형과 경유지

노선 도형은 정류장 사이를 도로를 따라 이어 만듭니다. 처음에는 OSRM 공개 서버를
썼는데, 그쪽 도로 데이터가 우리 추출본과 달라 경유지가 엉뚱한 길에 스냅됐습니다.
지금은 보행 그래프와 같은 원본(`walk.json`)으로 `driveroute.py` 가 직접 계산합니다.
버스가 이면도로를 잘 쓰지 않으므로 길 종류에 따라 가중치를 주고, 일방통행을
지킵니다. 네트워크 없이도 다시 빌드됩니다.

두 점을 최단으로 잇는 것만으로는 실제 회차 경로를 알 수 없습니다. 예를 들어 무은재삼거리는 버스가 온 길로
되돌지 않고 남동쪽 가지로 내려가 삼거리에서 북동쪽으로 꺾어 청암로로
올라가는데, 그냥 이으면 막다른 길처럼 그려집니다.

이런 구간은 `stops.py` 의 `VIA` 에 거쳐 가는 지점을 적어 줍니다. 경유지 첫
점은 **진행 방향이 정해지는 곳**이어야 합니다. 끝점만 주면 서비스 도로를 피해
크게 우회한 뒤 되돌아옵니다.

지도는 노선이 지나는 범위 밖으로 나가지 않습니다. 캠퍼스 셔틀 지도에서 전국을
볼 이유가 없고, 오프라인 타일 캐시도 쓸데없이 커집니다.

회차 고리는 **들어올 때와 나갈 때로 나눠** 적습니다. 한쪽에 한 바퀴를 다
넣으면 출구가 반대편일 때 한 변을 두 번 지납니다. 가속기가 그렇습니다 —
남쪽에서 올라와 반 바퀴 돌아 정류장에 들르고, 나오면서 나머지 반 바퀴를 돌아
남쪽으로 빠집니다.

지곡·유강은 출퇴근 단방향 노선이라 오전·오후가 서로 다른 경로입니다. 노선을
고르면 **출근·퇴근** 전환이 나오고 한쪽만 그립니다. 두 시간대를 함께 그리면
왕복 노선처럼 읽힙니다. 진행 방향 화살표도 함께 표시됩니다.


## 운행일

셔틀은 **평일만** 운행합니다. 원본 시간표에 요일 정보가 없어 확인한 내용을
`holidays.py` 에 두었습니다. 주말·공휴일에는 도착 목록과 지도 위 버스가 비고
그렇게 안내합니다.

공휴일은 [hyunbinseo/holidays-kr](https://github.com/hyunbinseo/holidays-kr) (MIT)
을 씁니다. 우주항공청 월력요항을 가공한 자료라 설날·추석 같은 음력 공휴일과
대체공휴일까지 들어 있습니다. 공공데이터포털 특일 API 와 달리 인증키가 필요
없어 빌드 때 받아 구워 넣습니다(`holidays_kr.json.gz` 에 캐시).

자료는 연 단위로 나옵니다. 올해 앞뒤 몇 해를 매번 훑으므로, 다음 해 자료가
올라오면 주간 갱신이 알아서 가져옵니다.

## 오프라인

시간표·노선·보행 그래프가 전부 정적 파일이라 지도 타일만 받아 두면 통째로
오프라인으로 동작합니다. 홈 화면에 추가하면 앱처럼 열립니다. 새 버전이
배포되면 화면 위에 알리고 누르면 새로고침합니다.


## 접근성

- 조작 요소에 모두 이름이 있습니다. 지도 마커도 정류장 이름을 가지며, 장식용
  마커(진행 방향 화살표, 내 위치, 경로 핀)는 탭 순서와 보조기기에서 뺐습니다.
  Leaflet 은 `interactive` 가 아니라 `keyboard` 옵션으로 탭 순서를 만듭니다.
- 정류장·경로 카드는 실제 `<button>` 이라 키보드로 누를 수 있고 눌림 상태를
  알립니다. 검색 결과는 `listbox`/`option` 입니다.
- 위치 안내는 `dialog` 로 초점을 받고, Esc 로 닫히며, 닫으면 초점이 원래
  자리로 돌아갑니다. Tab 이 카드 밖으로 새지 않습니다.
- 한 줄 요약은 `aria-live` 이지만 **내용이 바뀔 때만** 다시 씁니다. 매초
  고쳐 쓰면 읽어 주는 것이 끊이지 않습니다. 시계도 분이 바뀔 때만 이름을
  갱신하고 콜론은 보조기기에서 숨깁니다.
- 본문 글자는 흰 배경 기준 4.5:1 이상입니다. 노선 색도 흰 글씨를 얹으므로
  같은 기준으로 어둡게 잡았습니다. 색만으로 구분하지는 않습니다 — 배지에
  번호·이름이 있고 지도는 한 번에 한 노선만 칠합니다.
- 초점 표시가 보이고, `prefers-reduced-motion` 에서는 움직임을 멈춥니다.
  헤더를 건너뛰는 링크가 있습니다.


## 원본이 바뀌는 것

정적 파일에 다 구워 넣는 구조라 빠르고 오프라인도 되지만, **원본이 바뀌어도
알 수 없다는 대가**가 있습니다. 조용히 틀린 답을 주는 쪽이 문제입니다.

- **시간표** — `data.json` 은 안내 페이지에서 긁어온 것입니다. 학교가 바꿔도
  우리는 모릅니다.
- **공휴일** — 자료가 연 단위라 다음 해가 없으면 그날을 평일로 취급합니다.
- **방학 운행** — 따로 다루지 않습니다. 지금 시간표는 여름방학 중인 2026-08-03
  에 시행되어 학기가 시작된 뒤에도 그대로이고, 안내 페이지에도 방학·학기 구분이
  없습니다. 학기별로 나눠 운영한다는 근거가 없어 분기를 만들지 않았습니다.
  다르다는 것이 확인되면 그때 넣습니다.

`.github/workflows/refresh.yml` 이 매주 월요일 새벽에 원본을 다시 받아
`refresh.py` 로 재빌드하고, **달라진 것이 있을 때만** 커밋합니다. 커밋이 곧
배포입니다. 같은 입력이면 같은 파일이 나오도록 압축 타임스탬프까지 고정해
헛커밋이 생기지 않습니다.

주간 갱신이 세 번 넘게 걸러 마지막 확인이 21일을 넘기면, 화면이 스스로
"원본을 확인하지 못했습니다" 라고 알립니다. 워크플로가 멈추거나 원본이 사라져도
사용자가 날짜를 직접 읽어 알아채야 하는 상황을 만들지 않기 위해서입니다.

시간표가 바뀌면 자동 반영과 함께 **이슈를 엽니다** — 정류장이 늘거나 이름이
바뀌면 좌표(`STOPS`)·경유지(`VIA`)·영문 표기를 사람이 손봐야 하기 때문입니다.
이때 `source.json` 의 `effectiveFrom` 은 비워지고 화면에 "시행일 확인 필요"
가 뜹니다.

OSM 도로·건물은 자주 바뀌지 않아 기본에서 빠져 있습니다. 필요하면 Actions 에서
수동 실행할 때 켜거나 `python3 refresh.py --osm` 을 돌립니다.

## 시간표 출처

밝힙니다. 시간표가 바뀌었는데 모르고 쓰는 것이 이 앱에서 가장 조용히 위험한
상황이라서입니다.

현재 시간표는 **2026년 8월 3일(월) 시행**이며, 오후 지곡·유강 확장노선 출발
시각은 재안내(17:10 · 17:40 · 18:10)를 반영한 것입니다.
